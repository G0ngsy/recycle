# 구현·데이터 재검증 — 2026-10-12

## 결론

현재의 단일 물체 사진 분류 + OCR + 사용자 품목 확인 + 지역별 안내 구조를 유지한다. TACO 탐지 모델을 바로 앱에 추가하기보다 국내 실제 촬영 평가 데이터를 확보하는 것이 우선이다. 이번 검사에서 발견한 중복 변형을 정리해 모델을 재학습했고 사진 입력과 거의 단색인 사진 처리를 보완했다. 실제 휴대폰 정확도는 아직 검증되지 않아 실험 기능 표시와 필수 품목 확인을 유지한다.

## 기능 검사와 수정

- 사진 분석 API의 기존 OCR 필드와 저장 기록 호환성을 유지한다. 모델 누락·분류 실패·OCR 실패는 개별적으로 처리한다.
- JPEG/PNG만 업로드하도록 화면과 API 조건을 맞췄다. 업로드 원본은 최대 20MB·4천만 픽셀이고, 긴 변을 최대 1,600픽셀로 줄여 JPEG로 전송한다. HEIC·GIF·손상 사진은 화면에서 안내한다. API의 5MB 제한은 유지한다.
- 카메라 화면을 닫거나 다른 화면으로 이동하면 스트림을 종료한다. 권한 요청이 뒤늦게 완료돼도 취소된 카메라를 계속 켜두지 않는다.
- 거의 단색인 사진은 재질 분류를 실행하지 않고 다시 촬영하도록 안내한다. 이는 단순한 정보 부족 검사이며 물체 존재 판별 또는 미지 물체 탐지 기능은 아니다.
- 새 모델 기본 경로는 `backend/models/trashnet-reviewed-v2`이다. 환경 변수 `MATERIAL_MODEL_DIR`가 별도 지정돼 있다면 그 경로가 우선한다. 이전 모델은 비교용으로 보관한다.
- 반복 데이터 점검용 `backend/scripts/audit_project_data.py`와 직접 검토한 중복 목록 `backend/data/trashnet_reviewed_groups.json`을 추가했다. 유사도만으로 자동 삭제하지 않는다.

RTX 4070에서 분류층 5회·전체 미세조정 14회를 실행하고, 검증 macro-F1이 가장 좋았던 미세조정 9회 모델을 선택했다. 5회 연속 개선이 없어 조기 종료했다. 평가 데이터는 모델 선택·점수 기준 결정에 사용하지 않았다.

검증 정밀도 90% 기준을 적용한 뒤에도 평가 정밀도는 골판지 86.6%, 금속 85.5%, 플라스틱 86.6%였다. 검증 점수 기준은 실제 정답률 보장이 아니다. 평가 데이터로 기준을 다시 맞추지 않았다. 실험 기능과 모든 사진의 품목 확인 단계를 유지한다.

합성 음성 사례 검사에서는 흰색·검정·회색·녹색 단색 사진을 정보 부족으로 거절한다. 무작위 노이즈는 여전히 골판지 후보 점수 약 0.63을 낼 수 있다. 실제 배경·일반 물체를 포함하는 별도 평가가 필요하며 단색 차단으로 미지 물체 문제가 해결됐다고 주장하지 않는다.

## OCR 검사

공식 마크 원본 32종과 회전·어둡게·축소·흐림 변형을 합친 160건을 실제 EasyOCR로 실행했다. 원본 분류 일치율 **87.5%**, 세부재질 일치율 **84.4%**, 원본 평균 처리 시간 약 1.07초였다.

분류 목표 90%에 못 미친다. 기본 통합 테스트는 결과 기록 모드여서 통과했지만 출시 기준 충족으로 해석하면 안 된다. 일반팩·멸균팩 문자 인식과 무색페트·바이오 세부재질 매핑을 보완해야 한다. 도포첩합 표시 2종은 문자 없는 그림이어서 OCR만으로 판별할 수 없다. 마크 이미지 인식 또는 사용자의 별도 확인이 필요하다. TACO는 분리배출 마크 인식용 정답 데이터가 아니다.

## TACO 도입 판단

[TACO 공식 저장소](https://github.com/pedropro/TACO)는 도로·숲·해변 등 실제 배경의 쓰레기를 위치·영역별로 라벨링한 COCO 형식 데이터다. [논문](https://arxiv.org/abs/2003.06975)은 당시 1,500장·4,784개 주석을 설명하며, 실제 환경 탐지를 위해 더 많은 주석이 필요하다고 밝힌다. 이 수치는 논문 판본의 수치이며 새 다운로드 버전의 개수를 확인한 값은 아니다.

**현재 단일 물체 사진 분류의 필수 교체재는 아니다.** 여러 물체 선택 또는 배경에서 쓰레기 위치 찾기가 목표가 되면 도입하는 것이 적절하다. 구현 순서는 위치 탐지 → 사용자 물체 선택 또는 객체별 잘라내기 → 재질 후보·OCR → 품목 확인 → 기존 배출 안내이다.

TACO 전체 장면을 TrashNet의 6개 분류 폴더에 그대로 섞으면 한 장에 다른 재질이 함께 있어 잘못된 단일 정답이 생긴다. 분류에 활용하려면 객체별 잘라내기와 명확한 재질 매핑이 필요하다. 원본 이미지별로 먼저 학습·검증·평가를 분리한 뒤 잘라내야 같은 원본의 객체가 구간에 흩어지지 않는다. 공식·미검토 주석은 구분하고 희소 분류·모호한 ‘기타’는 검토한다.

이번 확인 범위의 프로젝트와 다운로드 폴더에서 TACO 원본을 찾지 못했으므로 TACO↔TrashNet 파일 중복은 검사하지 못했다. 나중에 이미지 원본을 확보한 뒤 픽셀 해시·유사도·원본 이미지 ID를 함께 비교해야 한다. TACO 모델을 이번에 다운로드하거나 앱에 연결하지 않았다.

## 재현 명령

최종 검증: 백엔드 61개 단위·API 테스트와 프런트엔드 19개 테스트, 타입 검사·린트·빌드, 변경사항 공백 검사를 통과했다. 기본 실행에서 제외된 OCR 통합 테스트는 별도로 실제 모델을 사용해 160건을 실행했다. 이는 OCR 분류 목표 미달을 없애는 결과가 아니다.

브라우저에서 새 평가 사진 `glass123.jpg`를 업로드하고 세종의 관리번호 `202656900000400003`을 선택했다. 유리 후보 점수 약 0.93과 입력 전 비활성화된 품목 확인 버튼을 확인한 뒤 ‘유리병’으로 확정했다. 실제 AI 배출 단계·주의사항과 공식 PDF 9·31쪽, 지역 기준일 2026-05-21이 표시됐고 브라우저 오류는 없었다. 별도 실제 API 요청에서도 새 모델 버전 `trashnet-20261012T020615Z`를 확인했다. 검정 단색 사진 요청은 후보 없이 `reason: low_information`을 반환했다. 실제 휴대폰 카메라 권한·기기 촬영은 이번 데스크톱 검사에서 검증하지 않았다.

프로젝트 루트에서 실행한다. 이미 생성된 출력 폴더는 덮어쓰지 않는다.

$env:TORCH_HOME="$PWD/backend/.cache/torch"
