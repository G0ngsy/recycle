# Recycle 개발 일지 — 2026-09-10

## 작업 목적과 범위

외부 AI·데이터베이스·배포 서비스에 연결하지 않고 Recycle 프로젝트를 로컬에서 설치, 실행, 빌드, 테스트할 수 있는 안전한 MVP 상태로 안정화했다. 지역 데이터 오류, 이미지 입력 검증, 브라우저 저장소 고갈, 직접 URL 접근, 내부 오류 노출과 같은 경계 사례를 우선 처리했다.

## 구현 내용

### 개발환경과 자동 검증

- Node.js 20과 Python 3.11을 `.nvmrc`, `.python-version`으로 명시했다.
- 백엔드의 안전한 기본값을 `backend/.env.example`에 추가했다. 실제 token과 password는 포함하지 않았다.
- 프론트에 `typecheck`, `lint`, `test` 명령과 ESLint/Vitest 구성을 추가했다.
- 백엔드 테스트용 최소 의존성을 `backend/requirements-test.txt`로 분리했다.
- GitHub Actions에서 프론트 typecheck/lint/test/build와 백엔드 compile/test를 실행하도록 구성했다.
- README에 설치, 실행, 검사, 지역 데이터 선택 정책과 보안 기본값을 기록했다.

### 지역 API와 데이터 정확성

- 지역 목록과 시군구 목록에 명시적인 Pydantic response model을 적용했다.
- 지원하지 않는 시도와 시군구가 다른 지역의 첫 레코드로 대체되던 동작을 제거하고 `404`를 반환하도록 변경했다.
- 시도만 선택한 경우 첫 공개 레코드를 대표 안내로 사용하되 응답의 `시군구명`은 비워 지역 정밀도를 과장하지 않게 했다.
- 동일 시군구에 관리구역별 데이터가 여러 개인 경우 첫 번째 일치 행을 사용하는 현 MVP 정책을 README에 명시했다.

### 프론트 사용자 흐름

- 지역 API 오류 시 전체 페이지를 새로고침하지 않고 API만 다시 호출하도록 변경했다.
- 입력 없이 `/region`에 접근하거나 필수 상태 없이 `/result`에 접근하면 홈으로 안전하게 이동한다.
- OCR이 분류를 찾지 못하면 사용자가 품목명을 확인·수정한 뒤 가이드 생성을 계속할 수 있게 했다.
- 갤러리 삭제 버튼의 클릭 이벤트가 결과 카드로 전파되지 않게 했다.
- `localStorage` 쓰기 실패를 감지해 사용자에게 안내한다.
- 신규 및 기존 기록에서 base64 이미지를 제거해 브라우저 저장 용량 고갈 위험을 낮췄다.
- API 오류 응답의 안전한 `detail`을 사용자 오류 메시지로 사용할 수 있게 했다.

### OCR 및 API 안전성

- EasyOCR를 CPU 기본값으로 변경하고 `EASYOCR_GPU=true`일 때만 GPU를 사용하게 했다.
- 이미지 API는 JPEG/PNG Data URL만 허용한다.
- 손상된 base64와 빈 이미지는 `400`, 기본 5MB 제한 초과는 `413`으로 처리한다.
- 이미지 처리와 가이드 생성의 예상하지 못한 예외는 내부 상세를 숨긴 일반화된 메시지로 반환한다.
- CORS 기본 허용 대상을 로컬 프론트엔드 두 origin으로 제한하고 GET/POST 및 Content-Type만 허용했다.
- Ollama와 Hugging Face client에 기본 20초 timeout을 적용했다.
- Hugging Face 모드는 token이 없으면 안전하게 fallback으로 전환된다.
- 모델이 생성한 `source`는 신뢰하지 않고 애플리케이션이 구성한 공공데이터/기본 안내 출처로 교체한다.
- `print` 기반 AI/API 디버깅을 Python logging으로 교체했다.

### 미사용·위험 코드 정리

- 브라우저 번들에서 API key 노출 가능성이 있던 미사용 Gemini 서비스를 삭제했다.
- `@google/genai`와 호환되지 않는 구버전 React Router 타입 의존성을 제거했다.
- React Router와 Vitest를 보안 패치 버전으로 갱신했다.
- Neo4j 마이그레이션, 외부 AI 연결, YOLO 학습·다운로드는 실행하지 않았다.

## 발견된 문제와 해결

- 기존 지역 조회가 시군구를 찾지 못하면 다른 지역의 첫 행을 반환했다. 잘못된 안내 위험이 있어 명시적인 `404`로 변경했다.
- 기존 CORS가 모든 origin과 method/header를 허용했다. 로컬 origin과 필요한 method/header로 제한했다.
- 이미지 base64에 형식과 크기 제한이 없었다. Data URL, MIME, decode, 크기 검증을 추가했다.
- AI 예외와 원문 일부가 로그·응답에 노출될 수 있었다. provider 상세는 기록하지 않고 사용자 응답을 일반화했다.
- 모델이 출처 문자열을 생성해 허위 근거가 표시될 수 있었다. 애플리케이션 소유 출처로 강제 교체했다.
- 과거 base64 이미지를 `localStorage`에 계속 보관해 quota를 소진할 수 있었다. 저장 시 모든 기록에서 이미지를 제거한다.
- 초기 npm 감사에서 React Router high 등 취약점이 확인됐다. 호환 패치 후 Vitest도 안전한 버전으로 올렸으며 최종 감사는 0건이다.

## 추가 구현: OCR 기준선과 관리구역 정확도

- 공식 재활용 표시 이미지 32개와 기대 category/material을 1:1로 연결한 manifest를 추가했다.
- manifest 중복, 누락, 자산 파일 불일치를 기본 테스트에서 검증한다.
- 실제 `preprocess_image()`와 `detect_recycle_mark()`를 실행하는 OCR integration test를 추가했다.
- 원본 외에 5도 회전, 밝기 저하, 60% 축소, 3px blur 변형을 메모리에서 생성해 총 160개 결과를 측정하도록 구성했다.
- OCR 실행 결과는 `backend/test-results/ocr-baseline.json`에 정확도, 평균 처리 시간, 케이스별 OCR 원문과 판정 결과로 저장한다.
- 테스트 도중 모델을 다운로드하지 않도록 사전 준비된 `EASYOCR_MODEL_DIR`을 요구한다. 현재 환경에는 EasyOCR 런타임과 모델 cache가 없어 명시적인 skip을 확인했으며 실제 정확도 수치는 생성되지 않았다.
- `시도 → 시군구 → 관리구역` 3단계 선택과 관리구역 API를 추가했다.
- 관리구역이 있는 시군구만 선택을 필수화하고, 없는 지역은 기존 흐름을 유지한다.
- 동일 관리구역의 배출요일·시작·종료·장소·방법이 모두 같은 행만 제거하고 서로 다른 규칙은 `wasteInfo.rules[]`로 모두 반환한다.
- 지역 규칙은 LLM context에서 제외하고 구조화된 공공데이터를 결과 화면에 직접 표시한다.
- 기존 localStorage 기록의 단일 지역 응답을 신규 다중 규칙 구조로 읽기 시 자동 변환한다.

## 남은 위험과 후속 작업

- EasyOCR/OpenCV/전체 운영 의존성을 포함한 실제 이미지 분석은 현재 환경에 런타임과 모델 cache가 없어 실행되지 않았다. 모델이 사전 준비된 환경에서 기준선 리포트를 생성해야 한다.
- LLM timeout은 client 수준으로 적용했지만 실제 Ollama/HF provider별 장애·지연 테스트는 수행하지 않았다.
- 동일 시군구 내 관리구역이 여러 개인 경우 첫 행만 사용하는 정책은 정확도 한계가 있다. 다음 단계에서 관리구역 선택 또는 데이터 집계 규칙이 필요하다.
- 프론트 테스트는 서비스 계층 중심이다. 카메라 권한 거부, 전체 라우팅, 품목명 보정 UI는 브라우저 E2E 테스트로 보강해야 한다.
- Tailwind CSS와 Google Fonts CDN 의존성이 남아 있어 엄격한 CSP나 오프라인 환경을 지원하려면 로컬 빌드 의존성으로 전환해야 한다.
- Starlette TestClient deprecation warning을 제거하려면 FastAPI/Starlette/httpx 조합을 함께 검토해야 한다.
