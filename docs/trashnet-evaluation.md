# TrashNet 첫 학습 결과 — 2026-10-10

> 2026-10-12 재검증에서 유사 중복 사진의 분리 문제가 확인돼 이 모델은 비교용으로 보관한다. 현재 앱은 중복 변형 20장을 추가 제외하고 재학습한 `trashnet-reviewed-v2`를 사용한다. 최신 결과와 남은 한계는 [프로젝트 재검증 보고서](project-audit-2026-10-12.md)를 참고한다. 아래 86.2%는 이전 데이터 분리에 대한 기록이며 새 평가와 직접 비교해 성능 향상으로 해석하지 않는다.

MobileNetV3 Small을 RTX 4070에서 학습하고 앱의 사진 분석에 연결했다. 현재는 실제 휴대폰 촬영 환경 검증 전의 실험 기능이다. 데이터 출처는 [garythung/trashnet](https://github.com/garythung/trashnet)이다.

## 데이터와 학습

- 원본: TrashNet resized 2,527장. 다운로드 폴더는 변경하지 않았다.
- 손상 이미지: 0장. 서로 다른 분류에 중복된 3개 그룹, 6장을 제외했다.
- 사용 데이터: 2,521장. 학습 1,762장, 검증 376장, 평가 383장.
- 분리·학습 seed: 42. 학습층 5회와 전체 미세조정 20회를 실행했다.
- 검증 macro-F1이 가장 높은 미세조정 19회 모델을 선택했다. 평가용 데이터는 모델 선택과 점수 기준 결정에 사용하지 않았다.
- RGB·EXIF 방향 보정 후 256 resize, 224 center crop, ImageNet 정규화를 평가와 API에 동일하게 적용한다.

## 성적

| 데이터 | 정확도 | Macro-F1 |
|---|---:|---:|
| 검증 376장 | 91.2% | 0.890 |
| 평가 383장 | 86.2% | 0.840 |

| 분류 | 평가 정밀도 | 평가 재현율 | 평가 수 |
|---|---:|---:|---:|
| 골판지 | 90.6% | 95.1% | 61 |
| 유리 | 89.2% | 76.3% | 76 |
| 금속 | 80.6% | 93.5% | 62 |
| 종이 | 87.2% | 91.1% | 90 |
| 플라스틱 | 87.0% | 83.3% | 72 |
| 기타 | 73.7% | 63.6% | 22 |

이는 임계값 적용 전 전체 예측의 성적이다. 평가용 유리 76장 중 5장을 플라스틱으로, 플라스틱 72장 중 4장을 유리로 오분류했다. 종이 90장 중 2장을 골판지로, 골판지 61장 중 3장을 종이로 오분류했다. 유리를 금속으로 오분류한 경우도 9건 있어 금속 후보를 특히 주의해야 한다.

## 후보 표시 기준과 한계

검증 데이터에서 최소 10건의 예측을 확보하면서 정밀도 90% 이상인 최소 모델 점수를 분류별 기준으로 선택했다. 기타는 기준을 확보하지 못했다. 낮은 점수, 기타 결과, 마크와 외관이 충돌하는 경우 추가 확인 안내를 표시한다. 모든 사진은 품목 확인 화면을 거치며 재질만으로 품목이나 재활용 가능 여부를 확정하지 않는다.

원본 데이터는 주로 흰 배경의 물체 사진이다. 빈 배경, 미지의 물체, 국내 포장재, 오염·코팅·복합재질, 실제 휴대폰 조명의 성능은 검증되지 않았다. 실제 촬영 평가 자료는 사용자가 확보해야 하며, 이 성적은 실생활 인식 정확도를 의미하지 않는다.

## 로컬 산출물

- `backend/data/trashnet/manifest.json`: 원본 검사·중복 제외·분리 기록.
- `backend/models/trashnet/model.pt`: 학습 모델, 약 6.2MB.
- `backend/models/trashnet/metadata.json`: 모델 버전·전처리·점수 기준·지표.
- `backend/models/trashnet/evaluation.json`: 학습 기록·분류별 지표·혼동행렬.
- `backend/.cache/easyocr`: 실제 API 검증용 한국어·영어 OCR 가중치.

데이터와 모델은 Git에서 제외되며 다른 환경에서는 README의 준비·학습 절차를 실행하거나 동일한 모델 폴더를 배치해야 한다. OCR 캐시를 재사용하려면 프로젝트 루트에서 `$env:EASYOCR_MODEL_DIR = "$PWD/backend/.cache/easyocr"`를 설정해 백엔드를 시작한다.

## 앱 검증

백엔드 56개 테스트, 프런트엔드 14개 테스트, 타입 검사·린트·프로덕션 빌드를 통과했다. 기본 OCR 통합 테스트 1개는 사전 모델을 요구하는 기존 정책에 따라 건너뛰었다. 별도로 실제 OCR 모델을 준비하고 브라우저에서 평가용 `glass123.jpg`를 업로드해 유리 후보(모델 점수 약 0.99), 품목 확인 단계, 공식 PDF 근거와 세종 지역 정보를 확인했다. 마크가 없는 사진은 품목 입력 전 안내 요청이 진행되지 않았다.

기존 EXAONE 호출은 두 번 모두 20초 응답 제한을 초과해 ‘확인 필요’로 표시됐고 원문과 지역 정보는 유지됐다. 이후 로컬 호출에 JSON 형식·컨텍스트 4,096 토큰·출력 최대 512 토큰·모델 유지 10분을 적용하고 기본 응답 제한을 60초로 조정했다. 안내 생성은 작업 스레드에서 실행해 다른 API 요청을 막지 않으며, 출력 제한으로 중단된 안내는 확정 결과로 사용하지 않는다.

보완 후 브라우저에서 같은 사진을 다시 업로드하고 품목을 ‘유리병’으로 확인했다. 실제 EXAONE 안내가 성공해 배출 단계 3개·주의사항 2개, 공식 원문 9·31쪽과 지역 데이터 기준일 2026-05-21을 함께 표시했다. 이는 해당 사진·품목·지역에 대한 흐름 검증이며 다른 실제 물체에 대한 정확도 검증을 의미하지 않는다.
